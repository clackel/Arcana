## 今日知识点

### 1. 使用 APIRouter 拆分新闻模块

`APIRouter` 解决了所有接口都堆在 `main.py` 中的问题。新闻路由统一设置 `/api/news` 前缀，并通过 `tags=["news"]` 在接口文档中分组；主应用再通过 `include_router` 完成挂载。

```python
router = APIRouter(prefix="/api/news", tags=["news"])
app.include_router(news.router)
```

因此，路由文件中的 `/categories`、`/list` 和 `/detail` 最终分别形成：

- `GET /api/news/categories`
- `GET /api/news/list`
- `GET /api/news/detail`

当前理解：已经能看懂模块化路由的创建、前缀拼接和应用挂载；尚无脱离教程重新拆分模块的证据。

### 2. 异步数据库与依赖注入

数据库配置使用 `create_async_engine` 创建异步引擎，使用 `async_sessionmaker` 创建 `AsyncSession` 会话。路由通过 `Depends(get_db)` 获得一次请求所需的数据库会话，不需要在每个接口中重复创建和关闭连接。

```python
async def get_db():
    async with AsyncSessionLocal() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
```

执行关系是：依赖创建会话 → `yield` 给路由和 CRUD 使用 → 正常完成后提交 → 异常时回滚 → 最终关闭会话。

当前代码使用 `mysql+aiomysql` 连接 MySQL。日志不记录源码中的真实连接凭据；数据库连接信息应放入环境变量或不纳入版本控制的配置文件。

### 3. ORM 模型映射

`Category` 对应 `news_category` 表，保存分类名称和排序值；`News` 对应 `news` 表，保存标题、简介、正文、封面、作者、分类、浏览量和发布时间。

`News.category_id` 通过外键指向分类表，并对分类 ID、发布时间建立索引，符合今天按分类筛选以及后续按发布时间排序的访问场景。

这里要区分：ORM 模型负责描述 Python 对象与数据库表之间的映射；CRUD 函数负责生成和执行具体 SQL 查询；路由负责 HTTP 参数和响应。

### 4. 获取新闻分类

分类接口接收 `skip` 和 `limit`，CRUD 使用 `offset(skip).limit(limit)` 查询分类记录：

```text
GET /api/news/categories
→ FastAPI 注入 AsyncSession
→ get_categories(db, skip, limit)
→ SELECT news_category OFFSET ... LIMIT ...
→ scalars().all()
→ 包装为统一 JSON 响应
```

该接口代码与 API 文档中的路径、参数名和默认值一致。

### 5. 获取新闻列表：分页、总量与 hasMore

接口从外部接收驼峰参数 `categoryId`、`pageSize`，通过 `Query(alias=...)` 映射为 Python 中的蛇形变量 `category_id`、`page_size`。

分页偏移量计算为：

```python
offset = (page - 1) * page_size
```

随后执行两次查询：一次读取当前页新闻，一次统计该分类的新闻总数。是否还有下一页由以下条件判断：

```python
has_more = (offset + len(news_list)) < total
```

这比仅判断“当前页是否正好有 `pageSize` 条”更准确，因为它使用数据库总量作为依据。

需要注意：当前查询没有显式 `order_by`，数据库不保证多次分页时记录顺序稳定。新闻流通常应按明确规则排序，例如发布时间或 ID 降序，但这属于后续改进，不能写成今天已经实现。

### 6. 获取新闻详情、浏览量与相关新闻

新闻详情接口依次完成三件事：

1. 按新闻 ID 查询详情，不存在则返回 HTTP 404；
2. 使用 SQLAlchemy `update` 将浏览量加一并提交；
3. 查询同分类、排除当前新闻的最多 5 条相关新闻，按浏览量和发布时间降序排列。

```text
GET /api/news/detail?id=<新闻ID>
→ 查询当前新闻
→ 不存在：抛出 404
→ 存在：数据库浏览量 +1
→ 查询同分类且 ID 不同的新闻
→ 按 views、publish_time 降序，最多 5 条
→ 组装详情与 relatedNews
```

这体现了路由组织业务流程、CRUD 各自封装单一数据库操作的分层方式。

### 7. CORS 中间件

CORS（跨域资源共享）用于解决浏览器前端与后端的协议、域名或端口不完全相同时，浏览器对跨源请求的限制。当前应用通过 `CORSMiddleware` 放行所有来源、方法和请求头。

该配置适合本地学习阶段快速联调。正式环境应列出可信前端来源。尤其在允许凭据时，不宜把来源长期配置为通配符，应结合实际前端地址验证浏览器行为和安全边界。

## 遇到的问题与代码发现

以下均为静态代码审查发现的潜在问题，不代表今天运行时已经实际报错。

### 1. 详情响应中的浏览量可能仍是更新前的值

代码先查询 `news_detail`，再直接执行 SQL `UPDATE views = views + 1`。由于会话设置了 `expire_on_commit=False`，提交后原有 `news_detail` 对象不会自动刷新。因此响应里的 `news_detail.views` 很可能仍是加一前的值，而接口文档示例期待返回增加后的浏览量。

验收方式：请求同一新闻详情前后查询数据库，并同时检查响应中的 `views`。后续可选择刷新对象、重新查询，或直接同步更新内存对象，但应避免重复加一。

### 2. 分页参数边界未完整限制

`pageSize` 只限制了最大值 100，没有限制最小值；`page` 也没有限制必须从 1 开始。零或负数可能产生不合理的 `offset` 或 `limit`。

验收方式：分别请求 `page=0`、`page=-1`、`pageSize=0` 和负数，确认接口是否应返回 422。

### 3. 新闻列表没有显式排序

分页查询只有筛选、偏移和数量限制，没有 `order_by`。没有稳定排序时，相邻分页结果可能重复或遗漏，尤其当数据同时发生新增或更新时。

验收方式：连续请求多页并重复请求同一页，检查顺序是否稳定；再决定符合产品要求的排序字段。

### 4. 时间默认值写法不一致

基类的 `created_at`、`updated_at` 使用了 `default=datetime.now()`，这会在模型导入时先计算时间；`News.publish_time` 使用 `default=datetime.now`，由插入记录时再调用。创建时间和更新时间通常也应在插入或更新时生成，需要进一步验证当前表结构和实际插入结果。

### 5. 测试文件尚未覆盖今日接口

`test_main.http` 目前只有根路径和一个代码中不存在的 `/hello/User` 请求，没有分类、列表、详情接口的测试用例。当前材料也没有接口响应或报错，所以只能确认代码存在，不能确认功能已经运行通过。

### 6. 数据库凭据安全

数据库连接信息直接写在配置文件中存在泄露风险。成品日志已隐去凭据。后续应改为环境变量；如果该凭据曾提交到远程仓库或发给他人，应及时更换。

## 容易遗忘或混淆的内容

- `prefix` 与装饰器路径会拼接，`/api/news` 加 `/list` 才是最终接口路径；
- `Query(alias="categoryId")` 解决外部驼峰参数与 Python 蛇形命名之间的转换；
- 页码不能直接传给数据库，先用 `(page - 1) * pageSize` 转为偏移量；
- 列表数据与总数是两种查询，`hasMore` 依赖偏移量、当前页数量和总数；
- `scalar_one()` 适合计数这种必须只有一个标量结果的查询，`scalar_one_or_none()` 适合最多一条的详情查询；
- SQL `UPDATE` 已经修改数据库，不等于之前查出的 ORM 对象会自动获得新值；
- 相关新闻必须同时满足“同分类”和“不是当前新闻”；
- 设计文档写出的完整功能不等于项目代码已经实现；
- 代码写完也不等于接口运行通过，仍需成功、空数据、非法参数和不存在资源等测试证据；
- CORS 是浏览器执行的跨源安全机制，不能把“后端允许请求”简单理解为所有客户端都会受同样限制。

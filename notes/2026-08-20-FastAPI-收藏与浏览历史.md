## 今日知识点

### 1. 收藏关系的数据模型

收藏不是新闻本身的属性，而是用户与新闻之间的关系。`Favorite` 表通过两个外键保存这层关系：

```text
Favorite.user_id → User.id
Favorite.news_id → News.id
```

模型还使用 `(user_id, news_id)` 联合唯一约束，表达“同一个用户对同一条新闻只能保留一条收藏记录”。单独限制 `user_id` 或 `news_id` 都不正确，因为一个用户可以收藏多条新闻，一条新闻也可以被多个用户收藏。

`created_at` 记录收藏时间，既能展示用户何时收藏，也能用于收藏列表的倒序排列。

### 2. 收藏接口的完整流程

收藏模块通过 `Depends(get_current_user)` 得到当前用户，不允许客户端自行指定 `user_id`。客户端只需提交新闻 ID，服务端把它与认证后的用户 ID 组合起来操作收藏记录。

主要接口包括：

```text
GET    /api/favorite/check   → 检查当前用户是否已收藏新闻
POST   /api/favorite/add     → 新增收藏记录
DELETE /api/favorite/remove  → 删除指定新闻的收藏记录
GET    /api/favorite/list    → 分页获取收藏的新闻
DELETE /api/favorite/clear   → 清空当前用户全部收藏
```

检查收藏状态使用 `scalar_one_or_none()` 判断记录是否存在，再转换为布尔值。取消收藏使用删除语句的 `rowcount` 判断是否真正删除到记录；没有命中时由路由返回 404。

### 3. 使用 join 查询收藏新闻列表

收藏列表不仅要返回收藏表中的 ID 和时间，还要展示新闻标题、简介、图片、作者等内容，因此需要把 `Favorite` 与 `News` 关联查询。

```text
以 News 为查询主体
→ 根据 Favorite.news_id == News.id 连接收藏表
→ 过滤当前 user_id
→ 按 Favorite.created_at 倒序
→ offset + limit 分页
→ 返回新闻对象、收藏时间和收藏 ID
```

查询使用 `label()` 为额外字段命名：

```python
Favorite.created_at.label("favorite_time")
Favorite.id.label("favorite_id")
```

路由再把新闻字段与这两个收藏字段组合，交给 `FavoriteListResponse` 完成字段校验和别名转换。

### 4. 收藏列表的分页与 hasMore

分页列表先单独统计当前用户的收藏总数，再查询当前页内容：

```python
offset = (page - 1) * page_size
has_more = total > page * page_size
```

当已展示的最大记录数仍小于总数时，`hasMore` 为 `true`。路由参数同时限制 `page >= 1`，并将 `pageSize` 限制在 1～100，避免产生无意义的负偏移或过大的单页结果。

### 5. 浏览历史模型与重复访问处理

`History` 使用 `user_id`、`news_id` 和 `view_time` 记录“哪个用户在什么时间看过哪条新闻”。浏览历史列表按 `view_time` 倒序排列，因此最近查看的新闻排在前面。

再次浏览同一新闻时，当前实现不会直接新增一条相同记录，而是：

```text
查询该用户对该新闻的所有历史记录
→ 按浏览时间和记录 ID 倒序
→ 已存在：更新最新记录的 view_time
→ 清理旧代码可能留下的重复记录
→ 不存在：新增一条历史记录
→ 提交并刷新 ORM 对象
```

这使同一新闻重新出现在历史列表顶部，同时避免列表中长期保留多条重复新闻。

### 6. 浏览历史列表的关联查询

历史列表与收藏列表使用相似的关联思路：以 `News` 为主体连接 `History`，筛选当前用户，再按浏览时间倒序分页。

不同点在于收藏列表附加 `favoriteId` 和 `favoriteTime`，历史列表附加 `viewTime`。两个列表共用 `NewsItemBase`，集中定义新闻 ID、标题、简介、图片、作者、分类、浏览量和发布时间，避免在多个 Schema 中重复声明相同字段。

### 7. 浏览历史的删除与清空

删除单条历史记录根据“当前用户 ID + 新闻 ID”共同限定范围，保证用户只能删除自己的记录。删除没有命中时返回 404。

清空历史只按当前用户 ID 删除，并通过 `rowcount` 得到受影响的记录数量。即使路由当前只返回“清空成功”，CRUD 仍然保留了删除数量，便于后续需要时展示结果。

### 8. 复用认证依赖保护业务数据

收藏和历史都属于用户私有数据。所有相关路由都先通过 `get_current_user` 验证 Token，再使用认证得到的 `user.id` 进行查询或修改。

```text
Authorization 请求头
→ get_current_user 验证 Token
→ 得到当前 User
→ 使用 user.id 操作 Favorite 或 History
```

这延续了前一阶段建立的认证能力，并把它真正应用到用户级业务数据隔离中。

## 核心执行流程

```text
客户端携带 Token 请求收藏列表

```

### 添加浏览历史

```text
客户端携带 Token 和 newsId
→ 认证依赖得到当前用户
→ 查询该用户是否看过该新闻
→ 已看过：刷新浏览时间并清理重复记录
→ 未看过：新增历史记录
→ 提交数据库
→ 返回统一响应
```

## 容易遗忘或混淆的内容

- 联合唯一约束限制的是同一组 `user_id + news_id`，不是分别限制两个字段；
- 收藏和历史列表需要新闻内容，因此要关联 `News`，不能只查询关系表；
- `label()` 为关联查询中的额外字段命名，便于路由组装响应；
- `offset` 是跳过的记录数，不是页码；
- `total > page * page_size` 表示当前页之后仍有数据；
- 收藏时间表示建立收藏关系的时间，浏览时间会在再次访问时刷新；
- 删除条件必须同时包含当前用户和目标新闻，避免操作其他用户的数据；
- Pydantic 内部可使用蛇形字段名，通过别名输出前端需要的驼峰字段；
- 认证依赖返回的 `user.id` 才是服务端可信的当前用户身份。
